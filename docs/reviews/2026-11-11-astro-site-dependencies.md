# Dependency reachability before the #45 expansion

Refreshed `pnpm audit --json` on 11 November 2026. The [compact registry results](2026-11-11-astro-site-dependencies.json) preserve advisory IDs, ranges and dependency paths. The registry reports three critical, 27 high, 26 moderate and five low version matches after the patch update below (53 distinct advisory URLs). These counts are dependency matches, not demonstrated reader-page exploits. This review classifies the critical prerequisites and the major affected execution boundaries; it is not an exhaustive exploit assessment of every transitive advisory.

| Dependency / advisory | Current evidence and exposure | Action |
| --- | --- | --- |
| Vitest UI/API, [GHSA-5xrq-8626-4rwp](https://github.com/advisories/GHSA-5xrq-8626-4rwp) | Previously 3.2.4. CI uses `vitest run`; no UI/API or Browser Mode server is configured. | Updated Vitest and its matching coverage package to patched 3.2.6. The unit and component suite passes. |
| Astro AVIF service, [GHSA-26w7-cxv4-gfx2](https://github.com/advisories/GHSA-26w7-cxv4-gfx2) | Astro remains 6.4.8. The advisory requires processing an untrusted AVIF image. Existing artwork is served directly from `public/brand`. | The migration does not introduce that input path. Upgrade Astro to at least 7.2.8 with its compatible integration/runtime and Sharp versions before adding image processing. Include that version-matrix review in #47's production-release gate. |

| Tinypool run options, [GHSA-85c8-ppgw-ccpr](https://github.com/advisories/GHSA-85c8-ppgw-ccpr) | Same dependency path. This is a residual developer/CI dependency finding, not a browser isolation guarantee. |

The remaining advisories cross these boundaries:

- React Router is used at build time for existing static reading components and in the lab's browser island. There is no deployed React Router SSR/RSC/action/manifest server or Turbo Stream deserialisation endpoint. Browser algorithm IDs are selected from the existing allowlist; report/MCP tools remain local scripts with their existing input contracts.
- Vite, PostCSS, source-map tooling, Browserslist, glob/brace parsing and related packages process the checked-out source during development/builds. They are not deployed as servers. Preview commands bind to loopback. Their advisory-specific input/platform conditions still need review when updating the toolchain; this does not classify arbitrary malicious repository content as safe.
- Sharp's native image-processing findings share the absent image-input path above. Installed build dependencies are not evidence that an image optimisation endpoint exists. Changing the image pipeline, adding server rendering, or accepting remote/user content requires a new reachability assessment.

The emitted Astro and legacy artifacts contain static documents, public reference files and browser assets. The migration adds no privileged backend or network-facing test runner. Production remains on the compatibility renderer until #47; that release must review dependency upgrades and actual hosting headers/analytics before cutover. The CSP/header inventory requested by the earlier review is retained in #47 rather than imposing an untested policy during this migration.
